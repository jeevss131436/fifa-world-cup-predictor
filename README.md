# World Cup 2026 Simulator

A monorepo that pairs a **Next.js** frontend (the main server) with a lightweight
**FastAPI** sub-server that runs the PyTorch match-prediction model. The browser
only ever talks to Next.js; requests to `/api/py/*` are rewritten to FastAPI.

```
world-cup-linreg/
├── simulator.py                 # your exported model wrapper (get_match_prediction)
├── world_cup_model.pth          # trained weights
├── scaler.pkl                   # feature scaler
├── data/
│   ├── schedule.csv             # source of truth for groups + fixtures
│   ├── team_value.csv           # raw exports ↓
│   ├── fifa_ranking.csv
│   ├── player_rating.csv
│   └── (squad_values.csv, processed_momentum.csv,
│         processed_squad_strength.csv)   # generated by preprocess.py
├── backend/
│   ├── main.py                  # FastAPI app: /predict /teams /groups /schedule
│   ├── teams.py                 # canonical team names, aliasing, group parsing
│   ├── preprocess.py            # builds the processed CSVs simulator.py reads
│   └── requirements.txt
└── web/
    ├── next.config.js           # rewrites /api/py/:path* -> 127.0.0.1:8000/:path*
    ├── app/
    │   ├── layout.tsx
    │   ├── page.tsx             # Single Match Predictor
    │   └── globals.css
    └── lib/api.ts
```

## How the pieces connect

`simulator.py` loads three *processed* CSVs (`squad_values.csv`,
`processed_momentum.csv`, `processed_squad_strength.csv`) that are **derived**
from the raw exports. The raw files spell countries inconsistently
(`USA`/`United States`, `Czechia`/`Czech Republic`, `Cabo Verde`/`Cape Verde
Islands`, …), so `backend/preprocess.py` normalizes every name onto the exact
spelling used in `schedule.csv` before writing the processed files. That keeps
the dropdowns, the schedule, and the model features all agreeing on one name per
team — all 48 group-stage teams resolve with zero "team not found" gaps.

> If you still have the exact dataframes used to train the model, drop them in as
> those three CSV filenames instead — `preprocess.py` is only a reconstruction.

## Setup

### 1. Python backend

```powershell
pip install -r backend/requirements.txt
python backend/preprocess.py          # generates the 3 processed CSVs
```

### 2. Web frontend

```powershell
cd web
npm install
```

## Run (two terminals)

**Terminal 1 — FastAPI** (must run from the repo root so `simulator.py`'s
relative paths resolve):

```powershell
$env:PYTHONUTF8 = "1"     # simulator.py prints an emoji; UTF-8 avoids a cp1252 crash
uvicorn backend.main:app --reload --port 8000
```

**Terminal 2 — Next.js:**

```powershell
cd web
npm run dev
```

Open <http://localhost:3000>. On Windows you can also run `./dev.ps1` from the
repo root to launch both at once.

## API

| Method | Path        | Body / Result                                              |
| ------ | ----------- | ---------------------------------------------------------- |
| POST   | `/predict`  | `{"home_team","away_team"}` → prediction dict              |
| GET    | `/teams`    | `{"teams":[...]}` — group-stage teams with full model data |
| GET    | `/groups`   | `{"groups":{"A":[...],...}}`                                |
| GET    | `/schedule` | `{"fixtures":[...]}` — group-stage fixtures                |
| GET    | `/health`   | `{"status":"ok"}`                                          |

Reach them from the browser through the proxy: `/api/py/predict`, `/api/py/teams`, …
